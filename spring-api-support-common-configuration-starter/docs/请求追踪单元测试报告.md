## 3. 已验证能力

### 3.1 分析服务

- 能按窗口聚合总请求数、可疑请求数、Top Path、Top IP、Top User。
- 能清理超出保留窗口的历史事件，并对 `snapshot(minutes)` 做默认值与上限归一化。
- 能在同一事件上同时命中 `burst`、`hotspot`、`spam`、`crawler`、`slow_request`。
- 能识别同一主体短时间错误集中触发的 `error_burst`。

### 3.2 过滤器

- 只有标注 `@RequestTraceStrategy` 的控制器或方法才会记录行为事件。
- 能正确提取请求方法、路径、路由模板、客户端 IP、浏览器、耗时、状态码等字段。
- 未登录请求不会因为 `userId` 为空而中断记录流程。

### 3.3 配置与存储

- `rawStorageType`、`behaviorStorageType` 写入前会做合法性校验，非法值直接拒绝。
- 已持久化的非法历史值在 `refresh()` 时会自动回退到默认值。
- 运行时配置 `request.trace.strategy.config-storage-type` 非法时会回退到 `database`。
- 原始记录文件存储可正常落盘，包含 `traceId`、IP、浏览器、指纹、请求地址、耗时等核心字段。

### 3.4 AI 摘要

- 已配置大模型客户端时，优先返回模型输出。
- 大模型未配置或返回空结果时，自动回退为规则摘要，不影响主流程。
- `aiSummaryEnabled=false` 时不会再调用模型，状态直接标记为 `disabled`。
- 超出 `aiRateLimitWindowSeconds` + `aiRateLimitMaxRequests` 限制时，会返回 `rate_limited` 并回退为规则摘要。
- 可疑事件快照会输出完整 AI 过程结果，包含 `status`、`summarySource`、`reason`、`model`、`promptDigest`、`latencyMs`。

## 4. 当前覆盖边界

本次单元测试已经覆盖：

- 请求采集主链路
- 核心策略分析主链路
- 配置归一化与配置校验
- 文件型原始存储
- AI 摘要回退链路

本次单元测试未覆盖：

- `database` 存储实现的真实落库行为
- `redis` 配置存储的真实读写行为
- 控制器接口的端到端 HTTP 交互
- 静态页面 `request-trace-live.html` 的浏览器端交互
- 真实大模型服务联调

这些内容应放到集成测试阶段验证，而不是继续塞进纯单元测试。

## 5. 建议的集成回归顺序

4. 对接真实 LLM 配置，验证 AI 摘要成功链路与失败回退链路。

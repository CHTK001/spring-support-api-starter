# 成就系统架构设计

## 一、整体定位

成就系统是一个独立的 `achievement` 子模块，与用户管理、角色管理、菜单管理等业务模块完全解耦。

**核心原则：不生产数据，只消费数据。**

其他模块负责上报用户行为，成就模块负责判定是否满足条件并解锁对应成就。

## 四、事件驱动架构

### 4.1 完整数据流

```
用户行为
  │
  ▼
┌──────────────┐
│ 签到/登录/浏览  │  ← 业务模块
│   发送消息等    │
└──────┬───────┘
       │
       │ 发布 UserActionEvent(userId, action, delta)
       ▼
┌───────────────────────┐
│  Spring Event 事件总线  │
└───────────┬───────────┘
            │
            ▼
┌─────────────────────────────────────────────────────┐
│          AchievementEventListener (异步)               │
│                                                      │
│  1. 行为类型 → 统计字段映射                            │
│     ┌──────────────┬──────────────────────┐          │
│     │ sign_in      │ → signInCount        │          │
│     │ login        │ → loginCount         │          │
│     │ menu_visit   │ → menuVisitedCount   │          │
│     │ message_sent │ → messageSentCount   │          │
│     │ frame_owned  │ → frameOwnedCount    │          │
│     │ rogue_play   │ → rogueCounter       │          │
│     └──────────────┴──────────────────────┘          │
│                                                      │
│  2. AchievementService.onUserAction(userId, statKey) │
│     ┌───────────────────────────────────────────┐   │
│     │ KvEngine.incr(key)  ── 更新统计值          │   │
│     │ KvEngine.hGetAll(prefix) ── 拉取上下文      │   │
│     │ RuleEngine.evaluate(rule) ── 逐条判定       │   │
│     │ UserAchievementMapper ── 写入已解锁记录    │   │
│     └───────────────────────────────────────────┘   │
│                                                      │
│  3. AchievementPushService.pushAchievements()       │
└─────────────────────────────────────────────────────┘
            │
            ▼
┌──────────────────────────────────────┐
│         前端成就推送                   │
│  {"type":"achievement_unlocked",      │
│   "data":[{"name":"登录达人 Ⅰ",        │
│            "badge":"🏅",               │
│            "description":"累计登录7天"}]}│
```

### 4.2 成就判定流程（详细）

```
  事件到达
     │
     ▼
┌─────────────────────┐
│ KvEngine.incr(key)  │  ← 原子更新统计数据
└──────────┬──────────┘
           │
           ▼
┌─────────────────────────┐
│ KvEngine.hGetAll(prefix)│  ← 拉取用户所有统计数据
│ → Map<String, String>   │
└──────────┬──────────────┘
           │
           ▼
┌──────────────────────────────────────────┐
│  遍历所有成就分组 (type)                   │
│  ┌─────────────────────────────────────┐ │
│  │ 获取该分组已解锁最高等级 currentMax   │ │
│  │ ┌─────────────────────────────────┐ │ │
│  │ │ 遍历该分组所有段位 (按 level 升序) │ │ │
│  │ │   跳过 level <= currentMax 的     │ │ │
│  │ │   ┌─────────────────────────┐   │ │ │
│  │ │   │ RuleEngine.evaluate()   │   │ │ │
│  │ │   │ (解析 JSON → 递归判定)    │   │ │ │
│  │ │   └───────────┬─────────────┘   │ │ │
│  │ │               │                 │ │ │
│  │ │         ┌─────┴─────┐           │ │ │
│  │ │         │ 满足      │  不满足    │ │ │
│  │ │         ▼           ▼           │ │ │
│  │ │   写入数据库   跳过继续下一条    │ │ │
│  │ │   构建DTO      段位              │ │ │
│  │ │   更新 currentMax               │ │ │
│  │ │   添加到 unlocked 列表           │ │ │
│  │ └─────────────────────────────────┘ │ │
│  └─────────────────────────────────────┘ │
└──────────────────────────────────────────┘
           │
           ▼
┌──────────────────────────┐
│  有解锁 → PushService    │
│  无解锁 → 静默返回        │
└──────────────────────────┘
```

## 五、KvEngine 存储抽象层

### 5.1 接口定义

```
KvEngine (接口)
  │
  ├── set(key, value)        — 写入键值
  ├── get(key)               — 读取键值
  ├── incr(key)              — 原子自增
  ├── decr(key)              — 原子自减
  ├── del(key)               — 删除键
  └── hGetAll(prefix)        — 前缀批量查询（判定上下文）
```

### 5.2 实现选型

| 实现类 | 适用场景 | 存储位置 | 配置方式 |
|-------|---------|---------|---------|
| FileKvEngine | 单机开发、小规模部署 | 本地文件系统 | `kvstore.type=file`（默认） |
| RedisKvEngine | 生产环境、多实例共享 | Redis 服务器 | `kvstore.type=redis` |

### 5.3 文件存储布局（FileKvEngine）

```
data/
└── kvstore/
    └── achievement/
        ├── 1001/
        │   ├── signInCount        → "7"
        │   ├── loginCount         → "12"
        │   ├── menuVisitedCount   → "28"
        │   ├── messageSentCount   → "3"
        │   ├── frameOwnedCount    → "2"
        │   └── rogueCounter       → "1"
        └── 1002/
            ├── signInCount        → "3"
            └── loginCount         → "7"
```

每个文件存一个值，文件名即字段名，文件内容为值。使用 ConcurrentHashMap 缓存 + 文件回写。

### 5.4 Bean 注入方式

```yaml
kvstore:
  type: file          # 开发环境：文件
  file-dir: data/kvstore
  # type: redis       # 生产环境：Redis
  # redis-host: localhost
  # redis-port: 6379
```

## 六、规则引擎设计

### 6.1 规则结构（JSON）

```json
{
  "type": "and",
  "conditions": [
    { "stat": "loginCount", "op": ">=", "value": 7 },
    { "stat": "signInCount", "op": ">=", "value": 5 }
  ]
}
```

### 6.2 逻辑组合

| type | 含义 | 说明 |
|------|------|------|
| and | 全部满足 | 所有 conditions 都为 true 才触发 |
| or | 任一满足 | 任意一个 condition 为 true 即触发 |

### 6.3 条件算子

| op | 含义 | 示例 |
|----|------|------|
| >= | 大于等于 | loginCount >= 7 |
| > | 大于 | loginCount > 100 |
| <= | 小于等于 | signInCount <= 30 |
| < | 小于 | messageSentCount < 1000 |
| == | 等于 | frameOwnedCount == 1 |
| != | 不等于 | rogueCounter != 0 |

### 6.4 判定流程

```
RuleEngine.evaluate(ruleJson)
  │
  ▼
解析 JSON → Map<String, Object>
  │
  ▼
evaluateNode(root)
  │
  ├── type == "and" → allMatch(subNodes)
  ├── type == "or"  → anyMatch(subNodes)
  └── 单一条件 → evaluateCondition()
                     │
                     ▼
              context.get(stat)
                     │
                     ▼
              Double.parseDouble(value)
                     │
                     ▼
              比较算子比较
                     │
                     ▼
              true / false
```

```java

public class SignInService {
    @Autowired
```

## 九、推送扩展

### 9.1 默认实现（日志）

```java
@Service
@Primary
public class AchievementPushService {
    @Override
    public void pushAchievements(Long userId, List<UnlockedAchievementDTO> list) {
        for (var a : list) {
            log.info("[成就推送] 用户 {} 解锁: {} {} {}", userId, a.getBadge(), a.getName(), a.getDescription());
        }
    }
}
```

### 9.2 WebSocket 扩展

```java
@Service
@Primary
public class WebSocketAchievementPushService implements AchievementPushService {
    @Autowired
    private WebSocketTemplate webSocketTemplate;

    @Override
    public void pushAchievements(Long userId, List<UnlockedAchievementDTO> list) {
        Map<String, Object> payload = new HashMap<>();
        payload.put("type", "achievement_unlocked");
        payload.put("data", list);
        webSocketTemplate.send(userId, payload);
    }
}
```

## 十一、注意事项

1. **KvEngine 实现选定后不要切换**，否则已有数据不会自动迁移
2. **incr/decr 必须是原子操作**，防止并发竞态
3. **规则 JSON 变更后需清除用户已判定缓存**，否则旧条件仍生效
4. **用户不触发行为就不会判定**，时间类成就需在行为发生时附带时间判断
5. **FileKvEngine 不适合多实例部署**，多实例必须用 RedisKvEngine

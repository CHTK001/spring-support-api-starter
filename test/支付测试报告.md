## RSA 密钥生成与配置

### 密钥生成
```bash
# 1. 生成 2048 位 RSA 私钥
openssl genrsa -out alipay_test_rsa.pem 2048

# 2. 提取纯净 PKCS8 私钥（无 PEM 头尾，纯 base64）
openssl pkcs8 -topk8 -inform PEM -outform PEM \
  -in alipay_test_rsa.pem -nocrypt | \
  grep -v "BEGIN\|END\|----" | tr -d '\n\r'

# 3. 提取公钥
openssl rsa -in alipay_test_rsa.pem -pubout
```

### 密钥配置流程
1. 生成 RSA 密钥对 → 提取 PKCS8 私钥和公钥
2. 私钥通过 `PaymentCipherService.encrypt()` AES 加密后存入 `pay_merchant_channel` 表
3. 公钥上传至支付宝沙箱开放平台（"自定义密钥"模式 → "公钥模式"）
4. 支付宝平台返回的支付宝公钥存入 `publicKey` 字段

## 三期代码变更（2026-05-14）

### Fix 3: JDK 21 PKCS8 私钥解析兼容性（isLikelyGarbage + extractBase64Key）

#### 3.1 PaymentCipherService.isLikelyGarbage() AES 误检测防护
**文件**: `PaymentCipherService.java`
- **问题**: AES/ECB 解密时，错误密钥不会抛异常，而是返回乱码。之前无法区分"密钥错误"和"解密成功"，导致多个候选密钥轮询时出现假阳性
- **修复**: 新增 `isLikelyGarbage()` 校验解密结果：
  - 出现替换字符 `�` 直接判定为乱码
  - 控制字符占比超过 30% 判定为乱码
  - 解密结果为 null/空也跳过

#### 3.2 extractBase64Key() — 解决 JDK 21 "extra data at the end" 错误
**文件**: `AbstractMerchantPaymentChannel.java`
- **问题**: 支付宝 SDK 内部 `RSAEncryptor.getPrivateKeyFromPKCS8()` 对**整个 PEM 字符串**（含 `-----BEGIN PRIVATE KEY-----` 标记）做 Base64 解码。标记文本中的 `B/E/G/I/N/P/R/V/A/T/K/Y/D` 等字符属于有效 Base64 字符，解码后产生冗余字节，JDK 21 的 `DerValue` 严格解析器抛出 `IOException: extra data at the end`
- **修复**: 新增 `extractBase64Key()` 方法，剥离 PEM 标记仅保留纯 Base64 内容。支付宝私钥仅使用纯 Base64 传递给 SDK，避免标记文本污染 DER 解析
- **修改文件**:
  - `AbstractMerchantPaymentChannel.java` — 新增 `extractBase64Key()` + `normalizePemKey()` 保留微信兼容
  - `AlipayWebPaymentChannel.java` — 支付宝私钥改用 `extractBase64Key(decryptValue(...))`
  - `WalletPayoutServiceImpl.java` — 同上
  - `PaymentNotifyServiceImpl.java` — 同上
- **测试结果**: `POST /api/wallet/order/recharge/pay` → 成功返回 HTML_FORM 包含沙箱表单

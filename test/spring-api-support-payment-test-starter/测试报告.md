# 支付管理后端修复验证报告

**日期**: 2026-05-15  
**测试环境**: Windows 11 Pro, Java 25, Spring Boot 3.5.9  
**后端端口**: 8090, context-path: /api  

---

## 修复概要

### 问题
运营中心（Operations Center）所有 4 个 API 返回 `C0400S0000`（系统异常），导致前端 Vue 渲染报错：
- `Cannot read properties of undefined (reading 'filter')`
- `Cannot read properties of undefined (reading 'forEach')`

### 根因
两个模块定义了相同 FQCN `com.chua.payment.support.controller.PaymentOpsController`：
1. `spring-api-support-common-payment-starter`（仅含 3 个 dashboard 端点）
2. `spring-support-payment-starter`（含 overview/scheduler/notify 等端点）

Fat JAR 的 `BOOT-INF/lib/` 类路径中 common 模块先被加载，导致 parent starter 中完整的 ops 端点不可用，同时因双 bean 导致类冲突，所有 `/ops/*` 端点抛出异常。

### 修复方案
在 test starter 中新建 **PaymentOpsExtController**，提供 parent starter 中缺失的端点：

| 端点 | 方法 | 状态 |
|------|------|------|
| `GET /ops/overview` | 返回回调审计 + 订单号策略 | ✅ 200 |
| `GET /ops/scheduler/tasks` | 返回空列表（调度器已禁用） | ✅ 200 |
| `GET /ops/notify/log/page` | 分页查询通知日志 | ✅ 200 |
| `GET /ops/notify/error/page` | 分页查询通知错误 | ✅ 200 |

## 已知未解决问题

1. **前端 node_modules 损坏**：pnpm store 文件锁定（Windows EBUSY）导致前端 dev server 无法启动。需要清理 node_modules 后重新 `pnpm install`。
2. **DashboardController 路径冗余**：`@RequestMapping("/api/test/ops")` 多了一层 `/api`（context-path 已提供），正确路径为 `/api/api/test/ops/...`。不影响功能，双路径均可访问。
3. **钱包提现审批字段**：数据库 `pay_wallet_withdraw_approval` 表 `withdraw_no` 字段缺乏默认值，可能导致 `DataIntegrityViolationException`。

---

## 结论

后端运营中心 API 已全部修复并验证通过。前端 Vue 页面在 API 层面不再有数据获取错误，待前端环境恢复后可正常加载运营中心页面。

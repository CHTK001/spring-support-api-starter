# 基准测试结果

> 运行方式:
> 1. 启动 Rust 服务器: `mvn spring-boot:run -pl test/spring-api-support-rust-demo-starter -Dspring-boot.run.jvmArguments="-Djava.library.path=/c/tmp/rust-build/debug/ --enable-native-access=ALL-UNNAMED"`
> 2. 启动 Tomcat 服务器: `mvn spring-boot:run -pl test/spring-api-support-tomcat-benchmark`
> 3. 运行测试: `mvn -o -q exec:java -Dexec.mainClass="com.chua.starter.benchmark.BenchmarkRunnerMain" -Dexec.classpathScope=test`

## 3. IO 等待场景优势 (Delay 100ms)

| 并发度 | Rust (ops/s) | Tomcat (ops/s) | 倍率 |
|--------|-------------|----------------|------|
| 100 | 1,000 | 984 | 1.02x |
| 1000 | **9,165** | **2,256** | **4.06x** |

> 理论极限 = 并发度 / 延迟秒数 = 1000 / 0.1 = 10,000 ops/s。Rust 达 9,165 (92% 理论极限)，Tomcat 仅 2,256 (23%)。原因是 Rust 虚拟线程在 sleep 时自动 unmount，不阻塞 tokio worker；Tomcat 平台线程在 sleep 时仍占用线程池。

## 6. 关键结论

| # | 结论 | 数据支撑 |
|---|------|---------|
| 1 | **低并发下两者持平** | 并发 100 时 Rust/Tomcat 倍率 0.79~1.12x |
| 2 | **IO 等待场景 Rust 优势极大** | Delay 100ms 并发 1000 时 Rust 4.06x Tomcat |
| 3 | **高并发下 Rust 吞吐更高** | 并发 10000 时 Rust 2.25~2.98x Tomcat |
| 4 | **高并发下 Rust 错误率更低** | 并发 10000 时 Rust 0~19% vs Tomcat 6.6~39% |
| 5 | **Tomcat 受 max-connections 限制** | 并发 10000 时 Tomcat 大量错误 (超过默认 8192 连接上限) |
| 6 | **共享 HttpClient 下 Tomcat 小请求略快** | 可能是 Tomcat NIO + 成熟线程池的优化优势 |

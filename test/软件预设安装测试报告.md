## 测试方法

1. **预设导入测试** — 通过 `POST /v2/project/container/software/binding/importPreset` 导入预设，验证 bindingRemark JSON 字段正确提升（port / dockerImage / dockerEnv / dockerVolumeMappings / dockerSecurityOpts / dockerCommand）
2. **Docker run 命令验证** — 验证 `buildDockerRunCommand()` 生成的 CLI 命令语法正确、参数完整
3. **实际安装测试** — 通过 `POST /v2/project/container/software/binding/operate` 提交 INSTALL 操作，在远程 Docker 宿主机上创建容器
4. **一键安装完整链路** — 调度中心（58081）+ 执行器（58083）配合，验证 importPreset → updateBinding → operateBinding(INSTALL) → Dockerfile 构建 → 容器启动 → RUNNING

## 修复记录（2026-05-15）

### Nacos 预设修复

| 项目 | 修复前 | 修复后 |
|------|--------|--------|
| 预设类型 | SOFTWARE（`:v2.3` 镜像） | DOCKERFILE（基于 `:latest` 构建） |
| JVM 参数 | 使用 CMS GC 标志（JDK 25 已移除） | sed 剥离所有废弃标志 |
| seccomp | 无配置，线程创建被拦截 | `dockerSecurityOpts: ["seccomp=unconfined"]` |
| 内存 | 默认堆（内存不足） | `JAVA_OPT=-Xms256m -Xmx512m` |
| 认证 | 无认证配置 | 预置 NACOS_AUTH_TOKEN 及 IDENTITY 密钥 |
| 运行用户 | `USER nacos`（新版镜像无此用户） | 去掉 `USER nacos`，以 root 运行 |

### Kafka 预设修复

### ZooKeeper 预设修复

## 已知问题

| RocketMQ namesrv + broker 双进程 | 单容器同时启动 NameServer 和 Broker，日志混合 | ⚠️ 功能正常，但生产建议分离部署 |

# 时序数据查询键修复说明

## 问题描述

在 `MonitorSysGenServerComponentServiceImpl.queryTimeSeriesData` 方法中，构建时序数据查询键的格式不正确，导致无法正确查询到存储的时序数据。

## 问题分析

### 原始错误的键格式
```java
// 错误的键格式
String timeSeriesKey = REDIS_TIME_SERIES_PREFIX + indicatorName;
// 结果：monitor:timeseries:cpu_usage
```

### 实际存储的键格式
根据 `MonitorSysGenServerMetricsServiceImpl.saveMetricsToTimeSeries` 方法，实际存储的键格式为：
```java
// 实际存储格式
REDIS_METRICS_PREFIX + serverId + ":" + 指标名称
// 结果：SERVER:server:metrics:1:cpu_usage
```

### 存储的指标类型
系统实际存储的指标包括：
- `cpu_usage` - CPU使用率
- `memory_usage` - 内存使用率  
- `disk_usage` - 磁盘使用率
- `network_in` - 网络入流量
- `network_out` - 网络出流量

## 修复方案

### 1. 添加正确的常量定义
```java
// 服务器指标数据存储键前缀（与MonitorSysGenServerMetricsServiceImpl保持一致）
private static final String REDIS_METRICS_PREFIX = "SERVER:server:metrics:";
```

### 2. 修正 queryTimeSeriesData 方法
```java
@Override
public ReturnResult<Object> queryTimeSeriesData(Long componentId, String indicatorName, Long startTime, Long endTime, Integer step) {
    // 获取组件信息以获取serverId
    MonitorSysGenServerComponent component = getById(componentId);
    if (component == null) {
        return ReturnResult.error("组件不存在");
    }

    Integer serverId = component.getMonitorSysGenServerId();
    if (serverId == null) {
        return ReturnResult.error("组件未关联服务器");
    }

    // 构建正确的时序数据查询键
    String timeSeriesKey = REDIS_METRICS_PREFIX + serverId + ":" + indicatorName;
    
    // 执行查询...
}
```

### 3. 修正 executeComponentTimeSeriesQuery 方法
同样的修复逻辑应用到 `executeComponentTimeSeriesQuery` 方法中，确保COMPONENT类型的组件也能正确查询时序数据。

## 修复效果

### 修复前
- 查询键：`monitor:timeseries:cpu_usage`
- 结果：查询不到数据，因为键不匹配

### 修复后  
- 查询键：`SERVER:server:metrics:1:cpu_usage`
- 结果：能够正确查询到服务器ID为1的CPU使用率时序数据

## 测试验证

### 1. 组件数据查询测试
```java
// 测试CPU使用率查询
Long componentId = 1L;
String indicatorName = "cpu_usage";
Long startTime = System.currentTimeMillis() / 1000 - 3600; // 1小时前
Long endTime = System.currentTimeMillis() / 1000; // 现在
Integer step = 60; // 1分钟步长

ReturnResult<Object> result = componentService.queryTimeSeriesData(
    componentId, indicatorName, startTime, endTime, step
);
```

### 2. 支持的指标名称
- `cpu_usage` - CPU使用率
- `memory_usage` - 内存使用率
- `disk_usage` - 磁盘使用率
- `network_in` - 网络入流量
- `network_out` - 网络出流量

### 3. 查询键格式验证
确保查询键格式为：`SERVER:server:metrics:{serverId}:{indicatorName}`

## 注意事项

1. **serverId 必须存在**：组件必须关联到有效的服务器
2. **指标名称匹配**：indicatorName 必须与实际存储的指标名称一致
3. **时间范围有效**：startTime 和 endTime 必须在数据存储的时间范围内
4. **键格式统一**：确保查询键与存储键格式完全一致

## 相关文件

- `MonitorSysGenServerComponentServiceImpl.java` - 组件服务实现（已修复）
- `MonitorSysGenServerMetricsServiceImpl.java` - 指标数据存储服务（参考键格式）
- 前端组件查询相关文件需要使用正确的指标名称进行查询

## 总结

通过修正时序数据查询键的构建逻辑，现在组件数据查询功能能够正确访问存储在Redis时序数据库中的服务器指标数据，解决了之前查询不到数据的问题。

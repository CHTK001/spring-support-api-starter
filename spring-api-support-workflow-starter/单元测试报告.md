# 轻量级审批工作流引擎 — 单元测试报告

## 1. 概述

本文档为 `spring-api-support-workflow-starter` 模块的单元测试计划。该模块实现一个轻量级审批工作流引擎，支持动态节点配置（ScFlowEditor 前端集成）和幂等性保证。

### 测试范围

| 层级 | 覆盖内容 | 测试方式 |
|------|---------|---------|
| **Entity** | 实体类字段映射、注解有效性 | 构造+反射 |
| **Mapper** | MyBatis-Plus CRUD、唯一键约束 | H2内存数据库 |
| **Engine** | 状态机流转、节点路由、审批人分配 | 纯单元测试(Mock) |
| **Service** | 流程定义CRUD、发起/审批/驳回/撤销 | H2 + Mock |
| **Idempotency** | 幂等键去重、状态前移保护 | 重复请求测试 |
| **Controller** | REST API 入参校验、响应格式 | MockMvc |

### 测试技术栈

- **JUnit 5** (Jupiter) — 测试框架
- **H2 Database** (内存模式) — MyBatis-Plus Mapper 测试
- **Mockito** — Service 层 Mock
- **Spring Boot Test** — 集成测试
- **AssertJ** — 链式断言

## 3. Engine 核心引擎测试

### 3.1 状态机流转测试

```
测试用例矩阵:

初始状态    操作          预期结果
─────────────────────────────────────────
DRAFT       提交           → PENDING (创建首个Task)
PENDING     审批通过(末节点) → COMPLETED
PENDING     审批通过(非末节点) → PENDING (创建下个Task)
PENDING     驳回           → REJECTED
PENDING     退回           → PENDING (重置当前Task)
PENDING     撤销(发起人)     → WITHDRAWN
COMPLETED   重复审批        → 幂等返回, 状态不变
REJECTED    重复驳回        → 幂等返回, 状态不变
```

### 3.2 节点路由测试

| 场景 | 输入 | 预期 |
|------|------|------|
| 单一路由 | START → A → END | A 审批人收到任务 |
| 条件路由 | START → [条件] → A/B | 根据条件结果路由 |
| 会签(并行) | START → A‖B → END | A和B同时有任务，全部通过才流转 |

### 3.3 审批人分配策略测试

| 策略 | Mock 数据 | 预期分配 |
|------|-----------|---------|
| `ROLE` | SysRole(部门经理), SysUserRole(用户A) | 用户A |
| `DEPT` | SysDept(技术部), SysUser(deptId=技术部) | 部门下所有用户 |
| `USER` | 指定用户ID | 该用户 |
| `DEPT_HEAD` | SysDeptPrincipalRel(deptId=技术部, userId=张三) | 张三 |
| `UPLEVEL_DEPT_HEAD` | 技术部pid=CTO部, CTO部负责人=李四 | 李四 |
| `APPLICANT` | 发起人自己 | 发起人 |

## 5. 幂等性测试

### 5.1 流程发起幂等

```
请求1: POST /wf/inst { businessType: "leave", businessId: "1", idempotentKey: "leave:1:submit" }
  → 201 Created, wfInstId=1

请求2: POST /wf/inst { businessType: "leave", businessId: "1", idempotentKey: "leave:1:submit" }
  → 200 OK, wfInstId=1 (相同实例返回)
```

**实现机制:** `INSERT ... ON DUPLICATE KEY UPDATE` / try-catch 唯一键冲突 → SELECT

### 5.2 审批操作幂等

```
请求1: POST /wf/task/1/approve { comment: "同意" }
  → task_status=APPROVED

请求2: POST /wf/task/1/approve { comment: "同意" }
  → 任务已处理, 返回相同结果 (幂等)
```

**实现机制:** Task 状态检查 — 非 PENDING 状态直接返回当前状态

## 8. 边界条件测试

| 场景 | 预期行为 |
|------|---------|
| 空审批人分配(无匹配用户) | 抛出`NoAssigneeException` |
| 流程定义不存在 | 404 + 错误消息 |
| 任务不属于当前用户 | 403 + 无权操作 |
| 已完成的流程实例再次操作 | 400 + 状态异常 |
| 单节点流程 (START→END) | 提交即完成 |
| 循环图 (A→B→C→A) | 校验时拒绝(有向无环图校验) |
| 超大JSON配置 (>10KB) | 正常存储和读取 |

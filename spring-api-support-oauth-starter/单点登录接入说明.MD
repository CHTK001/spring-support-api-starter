# 单点登录接入说明

## 一、适用范围

- 服务端：`spring-api-support-oauth-starter`
- 客户端基础模块：`spring-support-oauth-client-starter`
- 客户端示例业务服务：`spring-api-support-system-starter`

## 二、目标

建立一套可中心化部署的单点登录体系：

- 由 `spring-api-support-oauth-starter` 统一承载认证、授权、Token、第三方登录与管理控制台
- 各业务模块通过 `spring-support-oauth-client-starter` 接入，不重复实现认证逻辑
- 支持从 `static` 联调模式平滑切到真实 OAuth 服务端

## 三、角色划分

### 3.1 OAuth 服务端

模块：

- `spring-api-support-oauth-starter`

职责：

- 用户登录、刷新、注销、升级
- Token 生成、解析、黑名单与在线状态管理
- AppKey / AppId 鉴权
- 第三方 OAuth2 登录
- 管理控制台 `/oauth/admin`
- 多协议服务端：HTTP / Armeria / RSocket / OAuth2

### 3.2 OAuth 客户端

模块：

- `spring-support-oauth-client-starter`

职责：

- 向 OAuth 服务端发起鉴权请求
- 将用户信息包装成 `Principal`
- 完成 Servlet 请求包装、角色与权限判断
- 根据配置选择 `static / http / armeria / rsocket / oauth2`

### 3.3 业务服务

示例：

- `spring-api-support-system-starter`

职责：

- 自己提供业务接口
- 不保存 OAuth 核心状态
- 只通过客户端 starter 接入单点登录

## 四、推荐架构

### 4.1 中心化模式

推荐正式环境使用：

- 仅部署一个 `spring-api-support-oauth-starter` 作为认证中心
- 业务模块不再自己实现登录，只接入 `spring-support-oauth-client-starter`
- Token、在线状态、黑名单统一由 OAuth 服务端负责

### 4.2 本地联调模式

推荐开发初期使用：

- 业务模块配置 `plugin.oauth.protocol=static`
- 不依赖真实 OAuth 服务端
- 适合前后端联调和本地快速开发

## 五、服务端接入

### 5.1 启动地址

默认配置见 `src/main/resources/application.yml`：

- HTTP：`http://host:19180/oauth`
- Armeria：默认独立端口，见 `application-dev.yml`
- RSocket：默认独立端口，见 `application-dev.yml`

### 5.2 服务端最小前置条件

- MySQL
- Redis
- OAuth 相关表初始化完成
- 基础系统表可供用户、角色、部门、租户等查询

### 5.3 服务端关键配置示例

```yaml
spring:
  datasource:
    url: jdbc:mysql://127.0.0.1:3306/oauth
    username: root
    password: root

server:
  port: 19180
  servlet:
    context-path: /oauth

plugin:
  oauth:
    server:
      protocols: [http, armeria, rsocket, oauth2]
      token-timeout: 7200
      refresh-token-timeout: 604800
      online: MULTIPLE
      max-online-count: 3
```

## 六、客户端接入

### 6.1 本地静态模式

适用：

- 前后端本地联调
- 未启动真实 OAuth 服务端

配置：

```yaml
plugin:
  oauth:
    protocol: static
```

特点：

- 客户端直接解析静态 token
- 不会调用远程 OAuth 服务端
- 不适合正式环境

### 6.2 HTTP 模式

适用：

- 标准内网服务间调用
- 优先保证兼容性和可观测性

配置示例：

```yaml
plugin:
  oauth:
    protocol: http
    address: http://127.0.0.1:19180/oauth
```

说明：

- 客户端通过 HTTP 调用 OAuth 服务端
- Bearer Token、Cookie Token、AppKey 鉴权都可沿此链路工作

### 6.3 Armeria 模式

适用：

- 高并发、异步化调用场景

配置示例：

```yaml
plugin:
  oauth:
    protocol: armeria
    address: http://127.0.0.1:9091
```

注意：

- 需要确认 Netty 版本兼容
- 当前历史测试中曾出现过 Netty 兼容问题，升级依赖时要先做编译与真实联调

### 6.4 RSocket 模式

适用：

- 响应式链路
- 双向通信

配置示例：

```yaml
plugin:
  oauth:
    protocol: rsocket
    address: tcp://127.0.0.1:7000
```

## 七、客户端最小配置建议

业务模块推荐至少具备以下配置：

```yaml
plugin:
  oauth:
    protocol: http
    address: http://127.0.0.1:19180/oauth
```

如果本地开发未启 OAuth 服务端，则改成：

```yaml
plugin:
  oauth:
    protocol: static
```

## 八、数据库与 Redis 要求

### 8.1 Redis 必须共享

OAuth 服务端和所有客户端最终依赖同一套 Token 状态语义，因此正式环境必须保证：

- OAuth 服务端连接的 Redis 是正式认证 Redis
- 客户端访问的 Token 实际由该 OAuth 服务端生成

否则会出现：

- Token 看起来存在，但服务端查不到
- 黑名单不一致
- 在线状态不一致
- 刷新、注销、升级行为异常

### 8.2 基础系统数据必须可读

OAuth 服务端认证成功后需要读取：

- 用户
- 角色
- 部门
- 租户
- AppKey / AppId

因此服务端依赖的数据源必须能访问这些核心表。

## 九、推荐迁移路径

### 9.1 从 static 切到真实 SSO

1. 启动 `spring-api-support-oauth-starter`
2. 初始化 OAuth 表与 AppKey / AppId
3. 业务模块把 `plugin.oauth.protocol` 从 `static` 改成 `http`
4. 配置 OAuth 服务端地址
5. 验证登录、刷新、注销、升级链路
6. 再逐步切到 `armeria` 或 `rsocket`

### 9.2 从单模块鉴权切到中心化 SSO

1. 所有业务模块统一接入 `spring-support-oauth-client-starter`
2. 停止业务模块内部私有鉴权逻辑
3. 把认证入口统一指向 OAuth 服务端
4. 统一 AppKey / AppId 管理
5. 统一 Redis 与用户体系

## 十、第三方登录接入

支持的典型平台包括：

- Gitee
- GitHub
- Google
- 企业微信
- 微信小程序
- 钉钉

接入时要准备：

- `client-id`
- `client-secret`
- `redirect-uri`
- 前端回跳地址

注意：

- 本地没有真实第三方凭证时，只能做失败分支与 state 过期分支测试
- 成功授权回调仍需真实环境联调

## 十一、常见问题

### 11.1 业务模块明明带了 Token，但总是认证失败

优先检查：

- `plugin.oauth.protocol` 是否还是 `static`
- OAuth 服务端地址是否正确
- Redis 是否为同一套
- Bearer Token / Cookie 是否按当前协议正确透传

### 11.2 HTTP 正常，Armeria / RSocket 异常

优先检查：

- 对应端口是否打开
- Netty 依赖版本是否兼容
- 客户端协议实现是否与服务端同时开启

### 11.3 登录成功后刷新或注销失败

优先检查：

- refreshToken 是否由同一 OAuth 服务端签发
- Redis 黑名单和 token 存储是否可见
- 客户端是否混用了不同环境的 token

## 十二、当前默认建议

- 开发环境：
  - 优先 `static`
- 集成环境：
  - 优先 `http`
- 高性能正式环境：
  - 在确认依赖兼容后再启用 `armeria` 或 `rsocket`

最稳妥的标准路径是：

- 先 `static`
- 再 `http`
- 最后按需要升级到 `armeria / rsocket`

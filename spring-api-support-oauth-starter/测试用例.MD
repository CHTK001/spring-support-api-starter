# OAuth 联调测试用例

## 范围

- 服务端：`spring-api-support-oauth-starter`
- 客户端：`spring-api-support-system-starter`
- 客户端基础能力来源：`spring-support-oauth-client-starter`

## 目标

本测试用例用于覆盖以下核心维度：

1. 正常登录
2. AppKey 鉴权
3. 加密 / 非加密
4. 多协议
5. Token 刷新 / 注销 / 升级
6. 指纹校验

## 模块关系

### 服务端

- 启动类：`com.chua.starter.oauth.sso.support.AuthApplication`
- 默认上下文：`/oauth`
- 特点：`spring.main.web-application-type=none`
  - 说明：不是传统 `servlet` 单协议服务，而是通过内部协议组件启动多协议服务

### 客户端

- 启动类：`com.chua.starter.system.SystemApplication`
- 默认端口：`18170`
- 默认上下文：`/system/api`
- 真实登录入口：
  - `POST /system/api/v2/user/login`
  - `POST /system/api/v2/user/refresh-token`
  - `DELETE /system/api/v2/user/logout`
  - `POST /system/api/v2/user/temporary-token`
  - `POST /system/api/v2/user/upgrade`

## 服务端协议覆盖

根据当前代码，服务端需要覆盖以下协议：

- `http`
- `armeria`
- `rsocket`
- `oauth2`

对应实现入口：

- `HttpOauthProtocol`
- `ArmeriaOauthProtocol`
- `RsocketOauthProtocol`
- `Oauth2Protocol`

## 鉴权方式覆盖

根据当前代码，服务端需要覆盖以下认证处理器：

- `DefaultAuthorizationHandler`
  - 普通 token 鉴权
- `JwtAuthorizationHandler`
  - JWT / Bearer Token 鉴权
- `AppKeyAuthorizationHandler`
  - AppKey 鉴权
- `AppIdAuthorizationHandler`
  - AppId 鉴权
- `OAuth2AuthorizationHandler`
  - 第三方 OAuth2 登录回调鉴权

## 加密覆盖

### 客户端侧

`spring-support-oauth-client-starter` 当前有两个关键开关：

- `plugin.oauth.enable-encryption`
  - 是否启用数据加密
- `plugin.oauth.key.enabled`
  - 是否启用 AK/SK

### 测试维度

必须覆盖以下四组：

1. 非加密 + 无 AK/SK
2. 非加密 + 有 AK/SK
3. 加密 + 无 AK/SK
4. 加密 + 有 AK/SK

## 本轮修复

- 修复 `AppKey` 多协议报文错误
  - 原问题：`http/armeria/rsocket` 客户端把整个 `AppKeySecret` 对象塞到 `x-oauth-user-code`
  - 修复后：改为发送真实 `appKey` 字符串，并兼容把 `body` 合并为 `code`/JSON 扩展字段
- 补齐 `RSocketProtocol#createTemporaryToken`
  - 原问题：`rsocket` 走到协议默认实现，直接返回“当前协议不支持临时令牌功能”
  - 修复后：`system + rsocket` 的临时令牌链路已真实通过
